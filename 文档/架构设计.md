# 架构设计

## 组件

### Android 应用

- Kotlin + Jetpack Compose：用户界面。
- Room + SQLCipher：本地结构化数据。
- Android Keystore + BiometricPrompt：数据库密钥封装和应用解锁。
- Health Connect：只读健康指标。
- Calendar Provider：读取忙碌时段，只写应用专属日历。
- WorkManager：复盘、提醒和备份任务。

### Windows Companion

- Python 3.13 + FastAPI + Pydantic + Uvicorn。
- 通过 Tailscale 私网接受已配对手机请求。
- DeepSeek 官方 Chat Completions：默认使用 V4 Pro/Flash 与 JSON 模式。
- AI小站 Responses API：经用户明确确认后手动启用，发送 `store=false`。
- Windows Credential Manager：按提供商分离、分段保存 API 密钥。
- `runtime/backups`：只保存手机生成的加密备份信封。

## 计划数据流

```text
本地画像 + 健康指标 + 忙碌时段
  -> 去标识和字段预览
  -> Windows Companion
  -> 当前手动选择的 AI 提供商
     - DeepSeek 官方 Chat Completions + JSON mode
     - AI小站 Responses API + store=false
  -> JSON Schema 计划草案
  -> 手机本地风险/冲突/预算校验
  -> 用户确认
  -> 应用数据库 + 应用专属日历 + 本地提醒
```

## 关键原则

- 固定日程、睡眠底线、已知医疗禁忌和预算上限属于硬约束。
- AI 输出始终是不可信输入，必须通过 Schema 和本地校验。
- 聊天不能直接改变日程；建议需转换成草案并再次确认。
- 中转端保持无状态；多轮对话摘要由手机本地维护并按需发送。
- 提供商不会自动故障切换；切到第三方前必须明确确认，手机显示当前接收方。
- AI 请求携带手机已确认的 `X-AI-Provider`；电脑端在鉴权和防重放后核对当前提供商，不一致时返回 409 且不调用模型。
- 手机离线或电脑不可达时，已有计划、记录和本地提醒继续工作。
